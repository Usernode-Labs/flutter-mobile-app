## How to use this doc

### Plan a new milestone

Start ~1–2 weeks before the previous milestone closes.

1. Draft the new milestone block (template below). Update the **Near-term objective** only if it has actually changed.
2. Propose the slice — a set of issues across initiatives. Each must be well-scoped, assigned, and carry one of the 11 [`init:*` umbrella labels](initiatives/) (the umbrella set is fixed). Poorly-scoped trackers get split first.
3. Walk 1:1s with each owner. Owner accepts, rejects, or proposes alternatives. Items not yet accepted are marked `(SHAPING)` next to the issue title in the slice — meaning *proposed but owner hasn't committed to it yet*.
4. Reconcile divergences. Only convene a small live meeting for the 2–3 items where people disagree — not the full team.
5. Each named person ticks their sign-off checkbox.
6. Apply the result on GitHub: set Milestone + Assignees on each slice issue. Run `/matrix` to refresh the auto block.

### Review mid-milestone

Weekly, or on demand.

1. Run `/matrix` to refresh the auto block.
2. Scan the slice table: items stuck in `In Progress`, owners overloaded, items not started.
3. If an owner flags "can't deliver":
   - First, scope down the issue (split, defer sub-tasks).
   - If not enough, drop the item from the slice. No re-sign-off needed — the slice is mutable.
   - If many items drop, the bet itself is at risk: clear the sign-off checkboxes and re-walk step 5 of the Plan workflow.
4. Do not add new items mid-milestone unless they replace dropped ones. New asks go to backlog or the next milestone.

### Close a milestone

On the due date, or shortly after.

1. Walk the success criteria. Tick each checkbox or note slippage.
2. For each slipped slice item, decide explicitly: into the next milestone's slice, or into its deferred list.
3. Write a brief retro paragraph in the closed milestone block:
   - Which pitches were unshaped at start and bit us?
   - Which estimates were systematically off?
   - Which deferrals turned out wrong?
4. Move the closed milestone block to `## Past milestones` so the live milestones list stays short.

### Anti-patterns to refuse

- Carrying a goal without slice items (`X should work well` with no concrete issues).
- Slice items with no owner.
- Quiet scope additions mid-milestone.
- Sign-off as a formality — if you'd actually disagree, raise it before ticking.
- Slipping a due date instead of dropping scope.
